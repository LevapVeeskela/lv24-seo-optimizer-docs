## New

### Bing sitemap submit

- **A real, gated Bing write.** The Integrations screen adds a sitemap submit card that builds
  `sitemap submit --provider bing --config <path> [--url <abs>] --allow-write [--confirm <token>] --json`.
  The engine sends the sitemap as a Bing Webmaster `SubmitFeed` request; only `--provider bing` is
  accepted, so the GSC path is never selected by the desktop.
- **Two phases, one reviewed plan.** Planning runs with the write opt-in but no token and only mints
  the plan; it does not call Bing. The card shows the engine's action, target, summary, plan hash,
  TTL, payload details and limitations. **Apply** sends the reviewed `--confirm` token. A cancelled
  or failed apply drops the plan and requires a fresh review.
- **API key.** The key comes from the `bing_api_key` secret (OS keychain, `LV24_SEO_BING_API_KEY` or
  the engine's opt-in file). A missing key is shown as `AUTH_REQUIRED` with a Settings hint, not as a
  generic failure.
- **Sitemap URL.** Leaving the field empty uses `{project.base_url}/sitemap.xml`; a supplied URL must
  be absolute `http(s)://` and is passed as `--url`.

### IndexNow from the sitemap

- **One action, no URL list to paste.** `indexnow_submit` builds
  `indexnow submit --from-sitemap --config <path> [--sitemap-url <abs>] --allow-write [--confirm <token>] --json`.
  The plan fetches and parses the sitemap read-only, extracts URLs, deduplicates them, skips URLs
  outside the IndexNow host and reports `truncated`, `total` and `limitations` instead of claiming a
  complete inventory.
- **Key and key location from config.** The host comes from `providers.bing.site`, the key from
  `providers.bing.indexnow_key`, and the hosted key file from
  `providers.bing.indexnow_key_location` or `https://<host>/<key>.txt`. A missing key is
  `AUTH_REQUIRED` with the expected key-file location.
- **The plan is bound to the sitemap.** Apply re-fetches the sitemap; if its URL set changed, the
  plan token is invalidated with `CONFIRM_REQUIRED` and nothing is submitted. A stable sitemap
  submits the refreshed list, capped at the IndexNow 10,000-URL limit.
- **Bounded result.** The result card shows the engine status/details and the submitted URL count,
  plus any skipped/duplicate rows and the truncated flag.

### Bing Site Scan opener

- **Opens the official page, nothing more.** Bing has no public API for starting a Site Scan in the
  official Webmaster method list, so `open_bing_sitescan` only opens
  `https://www.bing.com/webmasters/sitescan?siteUrl=<percent-encoded>` in the default browser. The
  host and path are hard-coded and re-checked before the opener runs; the webview cannot supply a
  destination.
- **No false success.** The desktop does not start, poll or import a scan, and the UI states that
  the scan is started on the Bing page. It never reports that a scan started.

### Per-session write secret

- **`LV24_SEO_WRITE_SECRET` is generated by the desktop.** At startup the shell draws 32 bytes from
  the OS CSPRNG, keeps the 64-character hex value only in Rust memory (zeroized on drop) and sets it
  on every engine child after `env_clear()`. It is never written to settings, argv, logs,
  diagnostics or the webview.
- **Plan tokens are session-bound.** The same secret is used for the plan and the apply in one app
  session; a new session gets a new secret, so an old plan token is rejected and the UI re-plans.
  The engine requires the secret even to mint a plan; CLI users set `LV24_SEO_WRITE_SECRET`
  themselves.

### Engine 0.9.0

- **Bing sitemap submit and one-click IndexNow.** `sitemap submit --provider bing` performs the
  gated `SubmitFeed` write with an idempotency ledger (a replay is `skipped`/`duplicate`, and a
  provider failure releases the claim). `indexnow submit --from-sitemap` resolves host, key and key
  location from `seo.toml`, parses `<urlset>` and bounded `<sitemapindex>` files, merges explicit
  URLs first and enforces the 10,000-URL cap. GSC sitemap submit, Bing sitemap delete and Yandex
  recrawl remain `WRITE_DISABLED`; no write adapter is claimed for them.
- **Configuration.** `providers.bing.indexnow_key` and optional
  `providers.bing.indexnow_key_location` are new; the Bing Webmaster API key stays a secret.
- **No surface growth.** The CLI still has 22 top-level commands; the MCP surface stays at 12 tools
  (only `seo_sitemap_submit` inputs changed) and the SQLite schema stays at version 4.

### Shell and contracts

- **`MIN_ENGINE_VERSION` is now `0.9.0`.** An installed `0.8.x` engine is reported as incompatible.
  The desktop needs `0.9.0` for `sitemap submit --provider bing` and `indexnow submit
  --from-sitemap`; a pre-`0.9.0` engine would answer `CLI_INVALID_JSON`.
- The committed contracts were regenerated from `lv24-seo 0.9.0`; the fixture envelopes change the
  version string and the `seo_sitemap_submit` input schema gains the optional `provider`. The full
  and `--static` contract checks pass.
- `scripts/cli-checksums.json` pins engine `0.9.0` with source
  `https://pypi.org/project/lv24-seo/0.9.0/`; the workflow default `engine_version` is `0.9.0`.

## Upgrade and known limitations

- Upgrading is unchanged: Windows NSIS, macOS `.app` and Linux AppImage update in place; deb, rpm,
  MSI and the portable ZIP remain manual. `0.1.0` still needs one manual install. The
  `0.6.0 → 0.7.0` in-app update was verified on Windows NSIS.
- **Bing Site Scan starts in the Bing UI.** The desktop only opens the official page. It does not
  start, monitor, cancel or import a scan, and it never claims one started.
- **IndexNow needs a hosted key file.** Besides `providers.bing.indexnow_key`, the key must be
  reachable at `https://<host>/<key>.txt` (or the configured
  `providers.bing.indexnow_key_location`). A missing or mismatched key file fails with
  `INVALID_INPUT` and the expected location.
- **Writes are not cancellable and have no rollback.** Sitemap submit and IndexNow are provider
  network writes, not cancellable background runs; a failed apply is not retried automatically and
  cannot be undone. Review a fresh plan before retrying.
- **Plan tokens expire.** A token is bound to the reviewed plan and the app session. A changed
  sitemap URL, a new app session or an expired TTL invalidates it; the UI then requires a fresh plan.
- GSC sitemap submit/delete, Bing sitemap delete and Yandex recrawl remain `WRITE_DISABLED`; the
  desktop shows that instead of turning it into a success.
- Linux and macOS sidecar pins remain `null`; the release workflow builds those sidecars and the
  release gate requires a rebuild-aware checksum report per target.
- OS packages remain unsigned (Windows, Linux) or ad-hoc signed (macOS); SmartScreen, Gatekeeper and
  antivirus warnings are possible. Verify `SHA256SUMS.txt`.
