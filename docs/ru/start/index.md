# Быстрый старт

LV24 SEO Optimizer — SEO-контур управления с приоритетом бесплатных источников для людей и AI-агентов. Он собирает Google Search Console, Яндекс.Вебмастер, Яндекс.Метрику, Bing/IndexNow, Chrome UX Report и PageSpeed Insights в одну нормализованную историю, добавляет ограниченный технический обход вашего сайта и превращает результат в недельные отчёты, команды CLI, MCP-инструменты и навыки агентов.

Пакет Python `lv24-seo` — основной движок. Настольное приложение — оболочка Tauri вокруг того же движка; она не переписывает SEO-логику и клиенты провайдеров. В пути по умолчанию нет платной платформы, парсинга выдачи и аккаунта вендора.

## Путь за пять минут

Установите движок:

```bash
uv tool install lv24-seo
```

Создайте рабочую область, проверьте машину и прочитайте первый снимок:

```bash
lv24-seo init --property https://example.com
lv24-seo doctor
lv24-seo stats --days 7 --json
```

`init` записывает `seo.toml` и создаёт `<config dir>/data`; относительный `data_dir` привязывается к файлу конфигурации. `doctor` работает офлайн: проверяет Python, файл конфигурации, эффективный каталог данных и его область, запись в текущий каталог и наличие токенов, но не делает сетевых вызовов. `stats` работает только на чтение и возвращает один ограниченный конверт для панели: текущее и предыдущее окна, статус каждого провайдера, покрытие, возраст данных, усечение и ограничения.

Конверт `stats` содержит `period`, `previous_period`, `generated_at`, массив `services` и сводку `coverage`. У каждой карточки сервиса есть `provider`, `label`, `configured`, `ready`, `status`, `metrics`, `previous`, `rows`, `data_age_days`, `truncated`, `limitations`, `warnings` и `error`. `status` принимает одно из значений `ok`, `no_data`, `missing_token`, `not_configured` или `error`.

`coverage.complete` истинно только тогда, когда каждый настроенный сервис имеет статус `ok`, вернул строки, не усечён и ни один сервис не пропущен и не завершился ошибкой. `previous` есть только для сопоставимых текущего и предыдущего окон (GSC, Яндекс.Вебмастер и Метрика); Bing, CrUX и PSI возвращают `null`. Метрики содержат только реально полученные значения: без заполнения нулями и без сводных итогов по разным источникам.

Когда будете готовы, добавьте токен провайдера:

```bash
lv24-seo auth login --provider gsc
lv24-seo auth set --provider gsc --stdin
```

`auth set` читает секрет из stdin или скрытого приглашения, но никогда из argv. Для хранения в системном keychain нужен необязательный extra `secrets`; установите `uv tool install "lv24-seo[secrets]"` или используйте переменные окружения. Наличие токена не доказывает, что он действителен и имеет нужные права.

## Требования

- Python 3.11 или новее. `uv` может сам предоставить интерпретатор, поэтому системный Python не обязателен.
- Учётные данные провайдеров, которые вам нужны: OAuth-клиент GSC (или сервисный аккаунт), OAuth Яндекс.Вебмастера/Метрики, API-ключ Bing Webmaster и API-ключ CrUX. PageSpeed Insights работает без ключа с меньшей квотой. У всех источников по умолчанию есть бесплатный тариф.
- Node.js 18 или новее — только для лаунчера `npx @lv24/seo`. Python CLI не требует Node.
- Сетевой доступ к API провайдеров. У инструмента нет телеметрии, сам по себе он ничего не отправляет.
- Для настольного приложения: Windows 10/11 x64 с WebView2, Linux x64 с glibc 2.35 или новее либо macOS 13 или новее.

GSC, Yandex Webmaster и Yandex Metrika могут использовать OAuth-коннектор (`auth login`), а GSC также принимает сервисный аккаунт (`providers.gsc.service_account_file` / `LV24_SEO_GSC_SERVICE_ACCOUNT_FILE`); обычный токен продолжает работать. Bing, IndexNow, CrUX и PSI используют API-ключи, потому что у этих провайдеров нет OAuth.

## По умолчанию только чтение

По умолчанию инструмент не меняет состояние провайдеров. `stats`, `doctor`, `config show`, `properties`, `gsc query`, `yandex queries`, `yandex indexing`, `bing quota`, `bing sitemaps`, `bing issues` и `report diff` вообще ничего не записывают. `report weekly` без `--send` только строит и сохраняет локальный снимок; `crawl` пишет только в локальное хранилище SQLite; `init` записывает `seo.toml` и создаёт `<config dir>/data`.

Операции записи к провайдерам защищены. План требует `--allow-write` и `LV24_SEO_WRITE_SECRET` и возвращает план и `confirm_token`, не обращаясь к провайдеру; для применения нужен свежий `--confirm <token>` в течение пяти минут. При инициализированной рабочей области применяется SQLite-журнал идемпотентности: повторный токен возвращает `skipped` / `duplicate`, и провайдер вызывается один раз. Без каталога данных применение всё равно выполняется, но конверт предупреждает, что защита от повтора отключена на пять минут жизни токена. Отправка sitemap в Bing, отправка URL в Bing, IndexNow и переобход в Яндексе действительно пишут; отправка sitemap в GSC и удаление sitemap в Bing возвращают `WRITE_DISABLED`, а не делают вид, что путь провайдера подключён.

MCP-сервер по умолчанию работает только на чтение; его инструменты записи помечены и защищены, а некоторые пути провайдеров всё ещё возвращают `WRITE_DISABLED`. Настольное приложение требует диалога подтверждения с точным именем цели, прежде чем отправить отчёт, установить задание планировщика, добавить запись MCP-клиента или выполнить запись к провайдеру.

## Интерфейсы

| Интерфейс | Что он даёт |
|---|---|
| CLI | Каждая команда поддерживает `--json`, стабильный конверт и документированные коды выхода. |
| MCP | stdio-сервер с 12 инструментами, 3 ресурсами и 3 промптами для Claude, OpenCode, Cursor и других клиентов. |
| Настольное приложение | Оболочка Tauri 2 + React с выбором рабочей области, панелью статистики, формой настроек, выводами конфигурации, отчётами, рекомендациями и подписанными обновлениями. |
| Автоматизация | Генераторы cron, systemd timer и Windows Task Scheduler, а также доставка через SMTP и Telegram. |

Конверт CLI — `{ok, data, meta, warnings}`. `meta.complete` равен `false`, когда входные данные отсутствуют, усечены или сэмплированы, а `meta.limitations` объясняет, что нужно учесть перед тем, как доверять числу. Те же правила честности действуют для MCP-ответов и отчётов.

## Необязательное приложение

Настольное приложение — версия `0.9.2` с движком `lv24-seo 0.14.0`; оно требует движок `0.14.0` или новее, поэтому установленный движок `0.13.x` несовместим. Оно полезно, когда не хочется помнить флаги: создайте или выберите `seo.toml` в приложении, подключите GSC, Yandex Webmaster или Metrika через карточку OAuth Connect, посмотрите панель и карточку Indexing automation только для чтения, отредактируйте конфигурацию через проверяемую форму, запустите ограниченный обход, проанализируйте лог nginx, разберите задачи, создайте или восстановите переносимый backup, просканируйте папку сайтов в портфеле, сравните и экспортируйте недельные отчёты с атрибутированным дайджестом и карточкой CWV, прочитайте инспекцию и карты GSC, события/карты/очередь Яндекса, страницы/трафик/обход/URL/связки Bing, органические страницы/цели/измерения Метрики и аудиты/историю CWV в экране Diagnostics только для чтения, отправьте URL или sitemap в Bing, прочитайте квоту, фиды sitemap и проблемы обхода Bing, запустите IndexNow, откройте официальную страницу Bing Site Scan и скопируйте ограниченную рекомендацию как Markdown-промпт для агента. Автоматизация индексации доступна только в CLI и планировщике; `0.9.2` добавляет коннекторы, а не карточку статуса. Долгие задания движка идут в фоне с баннером окна и кнопкой **Cancel**; записи к провайдеру не отменяемы. Windows NSIS, macOS `.app` и Linux AppImage умеют обновляться автоматически; portable ZIP, deb и rpm обновляются вручную. Обновлятор останавливает только запущенные им sidecar и блокируется с `UPDATE_ENGINE_BUSY`, если остановить не удалось.

## Статус и ограничения

Движок — `0.14.0`; приложение — `0.9.2`. Известные пробелы до 1.0:

- GSC, Yandex Webmaster и Metrika могут использовать OAuth-коннекторы; GSC сохраняет резервный сервисный аккаунт, а Google-приложение в Testing истекает refresh token через 7 дней. Статический токен принимается, но не обновляется.
- Отправка sitemap в GSC и удаление sitemap в Bing возвращают `WRITE_DISABLED`; отправка sitemap в Bing, отправка URL в Bing, IndexNow и переобход в Яндексе действительно пишут и требуют ключей провайдера или квоты.
- Отправка URL в Bing сообщает `accepted`, а не «проиндексировано»; значения квоты — остаток, а не всего, и месячное окно может закончиться раньше. У `bing sitemaps` нет ошибок по отдельным URL, а у `bing issues` нет серьёзности и даты.
- Статистика и связки Bing возвращают `no_rows_for_window`, а не ноль показов; URL Inspection обрабатывает один URL за вызов и не является живым тестом.
- Приложение открывает официальную страницу Bing Site Scan, но не запускает, не отслеживает и не импортирует сканирование.
- `storage.raw_retention_days` зарезервирован; сырые архивы пока не пишутся.
- В приложении `0.9.2` есть экраны обхода, логов, задач, backup, восстановления, установки расписания, портфеля, индексации Bing и Diagnostics только для чтения. Долгие вызовы движка идут в фоне с баннером окна и кнопкой **Cancel**, но отмена — не откат, и очереди заданий нет; записи к провайдеру не отменяемы.
- `cwv collect`, `backup restore --to` и `schedule status`/`uninstall` доступны только в CLI; приложение рендерит сохранённые строки CWV, планирует восстановление на месте и устанавливает задания планировщика после подтверждения.
- `report indexing`, `report opportunities` и `report history` запланированы, но не поставлены.
- Логирование опционально: установите `LV24_SEO_LOG_LEVEL`, чтобы включить redacting-handler в CLI и `mcp serve`. Стабильным диагностическим интерфейсом остаётся конверт `--json`.

Неизвестные значения остаются неизвестными, а не заполняются. Это сделано намеренно: ограниченный ответ с явными ограничениями полезнее, чем аккуратно выглядящее число без покрытия.
