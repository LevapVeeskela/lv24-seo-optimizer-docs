# Настольное приложение

LV24 SEO Optimizer Desktop — локальная офлайн-оболочка Tauri v2 вокруг движка `lv24-seo`. Python CLI остаётся основным движком: он отвечает за клиенты провайдеров, правила обхода, анализ, сборку отчётов и доставку. Приложение добавляет React-интерфейс и мост к процессам на Rust, а не вторую реализацию SEO.

Релиз `0.2.0` — мультиплатформенное превью. Он включает `lv24-seo 0.5.1` как сайдкар PyInstaller onedir. Здесь нет облачного аккаунта, телеметрии, локального HTTP API и парсинга выдачи. Приложение общается с движком через фиксированный мост к дочернему процессу с белым списком команд.

## Что оно добавляет

- **Выбор рабочей области.** Выберите `seo.toml`, который должен использовать движок, через нативный диалог выбора файла в настройках. Выбранный путь к конфигурации — это идентичность рабочей области.
- **Панель статистики.** Показывает ограниченный конверт `stats`: одна карточка на каждого настроенного провайдера, текущие значения, сравнение с предыдущим окном, покрытие, возраст данных, усечение и ограничения. Изменения CTR показаны в процентных пунктах. Нет заполнения нулями и сводных итогов по разным источникам; неизвестное остаётся неизвестным.
- **Форма настроек и выводы конфигурации.** Экран Settings — редактируемая форма. Экран Configuration доступен только для чтения и содержит вкладки Overview, Effective, Source TOML, Diff, Validation, Doctor и Environment. Source TOML скрывает секреты и доступен только для чтения; сырого редактора TOML нет. Сохранение применяет точечные патчи, сохраняет комментарии и порядок ключей, проверяет конфигурацию движком, создаёт резервную копию с меткой времени (хранятся последние пять) и атомарно заменяет файл.
- **Отчёты.** Запускает недельный отчёт локально, записывает `report.json` и `report.html` в каталог данных приложения и открывает HTML в браузере по умолчанию. HTML отчёта никогда не встраивается в webview приложения.
- **Рекомендации и очередь агента.** Превращает находки отчётов и статистики в ограниченные Markdown-промпты. Промпт можно скопировать, экспортировать как `.md` или сохранить в локальной очереди агента со статусом. Очередь хранится в локальном хранилище webview; ничего не отправляется автоматически.
- **Секреты через stdin.** Поле токена — это поле пароля, которое один раз отправляется по IPC. Слой Rust передаёт его в `lv24-seo auth set --provider <p> --stdin`, обнуляет свой буфер и никогда не пишет значение в лог, хранилище MobX, localStorage, буфер обмена или диагностический пакет. После сохранения интерфейс показывает только наличие и источник.
- **Панель обновлений.** Проверяет подписанный `latest.json` при запуске и по запросу, показывает заметки к релизу и устанавливает обновление только после подтверждения.

Панель и экран отчётов построены на тех же командах движка, что и терминал:

```bash
lv24-seo stats --days 7 --lag-days 2 --json
lv24-seo report weekly --days 7 --lag-days 2 --json
```

## Типы установки

Скачивайте файлы приложения со страницы релизов проекта. Приложение отделено от установки Python-движка; оболочка может использовать встроенный сайдкар, явный `LV24_SEO_BIN` или соседнюю portable-раскладку.

| Сборка | Как устанавливается | Обновление в приложении |
|---|---|---|
| Windows NSIS | `LV24.SEO.Optimizer_0.2.0_x64-setup.exe` | Да |
| Windows portable ZIP | Распаковать всю папку и запустить `lv24-seo-desktop.exe` | Нет |
| Linux AppImage | `chmod +x` и запуск | Да |
| Linux deb | `sudo apt install ./*_amd64.deb` | Нет |
| Linux rpm | `sudo dnf install ./*_amd64.rpm` | Нет |
| macOS `.app` из DMG | Перетащить в Applications | Да |
| MSI | Этот проект его не выпускает | Нет |

Для Windows нужны ОС Windows 10/11 x64 и WebView2. Linux — только x64, сборка на Ubuntu 22.04 с базовой glibc 2.35. macOS требует версии 13 или новее; используйте DMG arm64 на Apple silicon и DMG x64 на Intel. Пакеты ОС не подписаны или подписаны ad-hoc, поэтому предупреждения SmartScreen и Gatekeeper ожидаемы. Перед запуском установщика проверьте `SHA256SUMS.txt`.

## Как работают обновления

Обновлятор читает подписанный `latest.json` с endpoint GitHub Releases проекта. Пакеты подписаны ключом minisign/Ed25519, публичная часть которого встроена в приложение. Включён `requireSignedVersion`, поэтому объявленная версия привязана к подписанному пакету.

- Приложение проверяет обновления один раз при запуске, молча, с таймаутом 30 секунд, и при нажатии **Check for updates**.
- Ничего не скачивается и не устанавливается автоматически. Панель показывает версию и заметки; **Download and install** запускает обновление. Несохранённый черновик конфигурации отключает кнопку.
- Принимается только версия больше текущей. Обновлятор не может откатить приложение на более старую версию.
- Ошибка подписи блокирует этот артефакт, помечает ошибку как неповторяемую и указывает на страницу релиза. Повторной попытки нет, и ошибка не превращается в предупреждение об офлайне.
- Windows запускает подписанный установщик NSIS в пассивном режиме; macOS заменяет `.app`; Linux заменяет AppImage. После установки приложение перезапускается; перезапуск в Windows выполняет установщик NSIS.

### Матрица автообновления

| Сборка | Автообновление | Что происходит |
|---|---|---|
| Windows NSIS | Да | Скачивает подписанный установщик `.exe`, запускает его в пассивном режиме, перезапускает приложение |
| macOS `.app` | Да | Скачивает подписанный `.app.tar.gz`, заменяет приложение, перезапускает |
| Linux AppImage | Да | Скачивает подписанный AppImage, заменяет его, перезапускает |
| Windows portable ZIP | Нет | Панель обновлений ведёт на страницу релиза; скачайте и распакуйте новый ZIP |
| Linux deb | Нет | Панель обновлений ведёт на страницу релиза; обновляйте через пакетный менеджер |
| Linux rpm | Нет | Панель обновлений ведёт на страницу релиза; обновляйте через пакетный менеджер |
| MSI | Нет | MSI не выпускается; установка через MSI считается ручной |
| Неизвестная сборка | Нет | Панель обновлений ведёт на страницу релиза |

Ручное обновление сделано намеренно. Установка deb/rpm принадлежит базе пакетов дистрибутива, MSI этот проект не выпускает, а у portable ZIP нет установщика, который можно заменить. Приложение определяет тип установленной сборки и отключает встроенный установщик для таких случаев; оно не делает вид, что ручной пакет был обновлён.

## Переключение рабочей области

Активный путь `seo.toml` — это идентичность рабочей области. При переключении на другую конфигурацию приложение очищает статистику, отчёты и путь к HTML-отчёту, прежде чем какой-либо экран покажет числа из предыдущего проекта. Первая загрузка только запоминает путь; последующее изменение считается переключением. Несохранённые черновики конфигурации общие для Settings и Configuration и живут только в сессии, поэтому сохраните их перед закрытием приложения.

## Keychain в Linux

В Linux CLI-раннер наследует переменные session bus и XDG runtime, которые нужны Secret Service (`DBUS_SESSION_BUS_ADDRESS`, `XDG_RUNTIME_DIR`, `TMPDIR` и связанные пути), но отфильтровывает посторонние переменные хоста. Это делает системный keychain доступным из процесса приложения. Само значение секрета по-прежнему передаётся только через stdin. Если keychain недоступен, используйте переменные окружения `LV24_SEO_*` или явно включённый файловый fallback движка.

## Обход в версии 0.2.0

Приложение показывает настройки обхода в форме Settings и выводит находки обхода в отчётах и рекомендациях. В интерфейсе `0.2.0` нет отдельного экрана Crawl, а у долгих вызовов движка нет прогресса задания и кнопки отмены. Запускайте `lv24-seo crawl` в терминале, когда нужен полный вывод обхода и сравнение покрытия sitemap.

## Основы устранения неполадок

| Симптом | Вероятная причина | Что делать |
|---|---|---|
| Нет рабочей области | Не выбран `seo.toml` | Запустите `lv24-seo init`, затем выберите файл в Settings |
| Движок помечен как офлайн | Движок отсутствует или ниже минимальной версии оболочки | Используйте встроенный движок или укажите совместимый движок в `LV24_SEO_BIN` |
| Предупреждение SmartScreen или Gatekeeper | Сборка ОС не подписана или подписана ad-hoc | Проверьте `SHA256SUMS.txt`, затем используйте документированный путь **Run anyway** или **Open Anyway** |
| AppImage не запускается | Нет FUSE 2 | Установите `libfuse2` или используйте deb/rpm |
| Проверка обновлений не работает | Endpoint GitHub заблокирован или нет сети | Останьтесь на текущей версии; молчаливая проверка при запуске не показывает ошибку |
| Кнопка обновления недоступна | Несохранённый черновик конфигурации или ручная сборка | Сохраните или отмените черновик либо скачайте пакет со страницы релиза |
| Ошибка подписи обновления | Пакет не соответствует встроенному ключу | Артефакт заблокирован; скачайте заново со страницы релиза и проверьте контрольную сумму |
| `missing_token` на карточке | Нет токена провайдера | Запустите `lv24-seo auth set --provider <p> --stdin` |
| `no_data` на карточке | Провайдер доступен, но строк за окно нет | Расширьте окно или проверьте ресурс и задержку данных |
| Долгий вызов выглядит зависшим | В 0.2.0 нет прогресса и отмены | Дождитесь таймаута команды; интерфейс показывает неопределённое состояние занятости |

## Известные ограничения

- У `0.1.0` нет обновлятора, поэтому один раз нужно обновиться вручную. Автообновление работает с `0.2.0` и далее.
- deb, rpm, MSI и portable ZIP обновляются только вручную. Сборок для Windows arm64 и Linux arm64 нет.
- Требуются macOS 13+ и glibc 2.35+. На более старых системах сборки могут не запуститься.
- Обновлятор устанавливает только более новую версию; для отката нужна ручная установка старого релиза.
- Обновлятору нужен доступ к endpoint GitHub Releases. Если endpoint заблокирован или сети нет, приложение остаётся на текущей версии.
- Внешний движок проверяется по версии и не входит в сборку. Интерфейс помечает его как внешний и проверяет минимальную версию.
- Заголовки, действия и шаги проверки рекомендаций приходят из движка и остаются на английском; переводится только окружающий интерфейс (en/ru/zh).
- Это превью `0.x`: вывод конфигурации, поведение обновлятора и детали интерфейса могут измениться до 1.0.
